Method

A skill is only useful when it changes the next move.

The pack is organized around failure boundaries. Each skill tells the agent when to stop guessing, what evidence is acceptable, and which findings are too weak to ship.

01

Start from the symptom, not the framework.

A11y, WebView, hydration, storage, and gesture bugs often look similar until the boundary is isolated.

02

Demand proof that survives review.

The useful unit is not a checklist item. It is a reproducer, assertion, screenshot, trace, or artifact tied to a claim.

03

Reject confident but unfalsified fixes.

Forty domain skills keep a PR-worthiness gate. The triage skill routes reports to the right one instead of pretending to verify a fix.

Proof Gates

What the page is promising.

The intro page deliberately avoids popularity claims. It describes the checked repository contract: 41 catalogued skills, 40 domain review gates, 10 eval files with 56 cases, and explicit evidence coverage.

Domain skills carry falsifiable review gates.

The pack audit checks every non-triage skill for a PR-worthiness gate, weak-finding rejection, and an output contract. The triage skill routes a report into those domains.

Evidence coverage is labeled instead of flattened.

The coverage map distinguishes primary sources, evaluation cases, candidate leads, and routing-only examples instead of presenting every skill as equally proven.

Universal wording protects reuse.

Skill instructions avoid repository-specific company, customer, private-URL, and local-tool assumptions while still naming public browser APIs and libraries when those names help route a real failure.
