## Evidence levels

## `webview-bridge-pages`

1. **`gronxb/webview-bridge` parses every WebView message as bridge JSON.** Evidence: `gronxb/webview-bridge@packages/react-native/src/createWebView.tsx:217-224` calls consumer `props.onMessage?.(event)` then immediately `JSON.parse(event.nativeEvent.data)`. Why: app-level `postMessage` or malformed payloads can break the bridge handler even when they are not bridge messages. Minimal PR: guard parse, schema/type check, and ignore/forward non-bridge messages. Level: **V1**.
2. **`gronxb/webview-bridge` can call web `onReady` before delayed native hydration finishes.** Evidence: `gronxb/webview-bridge@packages/web/src/linkBridge.ts:116-132` reads `window.__bridgeMethods__ ?? []` and subscribes hydration; `:165` calls `onReady?.(proxy)`. Why: delayed native registration can expose an incomplete bridge contract. Minimal PR: fire `onReady` after hydrate completes or emit a second hydrated-ready signal. Level: **V2**.

1. Start with the first **V1** candidate in each section; otherwise reproduce the clearest **V2** before filing. 3. Keep issue titles narrow and maintainer-owned: one behavior, one failing reproduction, one proposed patch. Do not pitch the skill pack in the issue body.
4. Only promote to README evidence after a maintainer acknowledges, accepts, or merges the fix.
